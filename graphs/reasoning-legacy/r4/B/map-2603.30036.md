# Map for 2603.30036

## Method
- L3 (Paper title): "Aligned, Orthogonal or In-conflict: When can we safely optimize Chain-of-Thought?" — the framework name
- L24-28 (Framework description): "We model LLM post-training as an RL environment where the reward decomposes into two terms: one term depending on final outputs and another term depending on the CoT. Our framework allows us to classify these two terms as aligned, orthogonal, or in-conflict before training." — core methodology
- L95 (In-conflict definition): "A reward pair is in-conflict if CoT text which achieves a high R_cot cannot describe the CoT computations which are needed to achieve a high R_out." — first classification category
- L101 (Orthogonal definition): "A reward pair is orthogonal if there exists CoT text that both achieves high R_cot and describes the CoT computations needed for high R_out." — second classification category
- L107 (Aligned definition): "A reward pair is aligned if CoT text that achieves a high R_cot necessarily describes CoT computations that would improve R_out." — third classification category
- L75-82 (Core assumption about text and computation): "We can consider the CoT tokens as intermediate computational states, and ask what intermediate information they hold during the model's computation. Throughout the paper, we call the information held in those intermediate computational states the CoT computation, and consider it separately from the text making up the CoT" — distinction between CoT text and computation

## Setup
- L157 (Heads-And-Tails environment): "A simple state-tracking task taken from Skaf et al. (2025), where models are asked to track the state of a coin over N rounds of being or not being flipped." — first base environment
- L161 (Backdoor-Easy environment): "A set of simple coding problems taken from a modified version of the Mostly Basic Python Programming Problems (MBPP) dataset" — second base environment
- L226-227 (GRPO algorithm): "We use a modified version of GRPO (Xie et al., 2025, CAPO;) that allows us to assign rewards on a per-token basis. Credit assignment is done either by prompting the CoT monitor to identify which tokens were most relevant to a reward decision" — learning algorithm specification
- L229 (Model used): "We present results for Qwen-3-14B in this section, with Gemma-3 results in appendix E." — model specification
- L231 (ICRL algorithm): "We also make use of an in-context RL algorithm (Moeini et al., 2025) using Claude Opus 4.5 as the policy model." — alternative learning approach
- L199-206 (Length penalty specification): "A penalty on generations which exceed a minimum threshold L_min: R_cot^len(p,c)=-max(0,|c|-L_min)" — reward function example

## Headline results
- L245-246 (Main finding): "Our classification was predictive of monitorability outcomes. As summarized in fig. 4, our a priori classifications correctly predict monitorability across both Heads-And-Tails and Backdoor-Easy: in-conflict rewards lead to near-zero monitorability, while orthogonal and aligned rewards preserve it." — core empirical claim
- L247-248 (Aligned reward results): "Aligned rewards improved performance in Heads-And-Tails. As shown in fig. 6, when considering N=42 flips, a policy trained only on R_out achieves random performance. Our aligned R_cot improves R_out performance relative to this baseline." — aligned rewards improve outcome performance
- L258-259 (In-conflict difficulty): "A key secondary finding is that in-conflict rewards are harder to optimize than orthogonal or aligned ones... Learning often fails with in-conflict reward pairs. Figure 4 shows that the proportion of seeds achieving high scores on both R_cot and R_out is substantially lower for in-conflict rewards than for other reward types." — optimization difficulty for in-conflict rewards

## Limitations
- L265-266 (Environment simplicity): "Our environments are relatively simple, and hence perhaps our empirical results do not generalize to real LLM post-training. Future work should run similar experiments on training distributions that are closer to production LLM RL training." — limited environmental realism
- L267-270 (Prediction difficulty): "It is difficult to know what level of performance is likely to cause issues in practice. Hence, whether a drop in monitorability will actually be observed is unclear. For example, many modern models are trained with length penalties without any observed drop in monitorability (Guan et al., 2025)." — unclear practical applicability
- L269-270 (Detection empirically): "Although we think that our framework is conceptually useful, we expect in many cases it may be unclear which category a pair of rewards falls into—hence, turning this into something we can measure empirically would be valuable." — classification ambiguity in practice
- L271-272 (Semantic drift): "Chain-of-Thought semantics might change during long training runs even without concrete incentives. Schoen et al. (2025) hypothesize that this effect occurs in some state-of-the-art reasoning models." — unexplained semantic changes

## Assumptions and conditions
- L93-94 (Core transparency assumption): "Our definitions rest on the assumption that models have a strong inductive bias towards transparency due to pre-training on human language, so that absent strong optimization pressure, the CoT will remain transparent" — fundamental assumption about model inductive bias
- L305-315 (Semantic assumption): "We assume that π_sem(CoT)∈S—that whatever information the model extracts from its CoT can, in principle, be expressed in natural language. This is a strong assumption; models may perform computations that don't map neatly onto human-understandable concepts." — strong assumption about expressibility
- L410 (Transparent initialization): "We assume the base policy uses human semantics: π_sem^base=h." — initial state assumption
- L548-551 (In-conflict at threshold definition): "The pair (R_cot,R_out) is in-conflict at input I and threshold τ if for all optimization budgets B such that the learned CoT c*(I,B) achieves R_cot(I,c*(I,B))≥τ: R_out^human(I,c*(I,B))<R_out^ref(I,B)" — condition for classification

### Pressure
- L59-60 (Reward decomposition): "We model LLM post-training as an RL environment with two terms: R_out which depends only on p and o, and R_cot which depends only on p and c. The total reward is then R=R_out(o)+R_cot(c)." — pressure from combined objective
- L200-203 (Length penalty pressure): "Training with length penalties is in-conflict across all of our base environments, since very short reasoning cannot transparently express the CoT computations the model is using. More specifically, we assume that to achieve high R_out the CoT computation must contain some minimal set of reasoning steps" — compression pressure test
- L223-224 (CoT monitor pressure): "CoT Monitor (In-Conflict). In Heads-And-Tails, R_cot penalizes the model whenever the CoT text appears to involve reasoning about a coin; in Backdoor-Easy, it penalizes reasoning that involves a backdoor." — monitor-based pressure
