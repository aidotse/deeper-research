## Method
- L18: "The model emits a routing token (NoThink/Short/Long) as the first token of its response and then reasons under that mode's shaped reward and hard token cap" — three-mode self-routing where model chooses reasoning length via discrete routing token.
- L25-28: "We overcome collapse with two mechanisms working together. First, hard per-mode token caps make the modes distinct by construction, so the routing label cannot decouple from behavior. Second, a simple balance term added directly to the advantage, similar to the load-balancing penalties used to discourage expert collapse in Mixture-of-Experts routing (Fedus et al. 2022), keeps the policy from settling on a single mode" — mechanism to prevent routing collapse using caps and balance penalties.
- L50-61: "GRPO optimizes a policy by sampling a group of $G$ outputs for each prompt $q$ from the current policy $\pi_{\theta_{\text{old}}}$. The policy maximizes a clipped surrogate objective with a KL penalty" — uses Group Relative Policy Optimization with clipped surrogate objective.
- L105-115: "Each mode has a base reward $b$ and a per-token discount $\gamma$ on the number of tokens $L_{i}$ generated after the routing token, with discounts set so that each mode is the reward-optimal choice over a specific length range" — reward surface with mode-specific bases and discounts to create distinct mode preferences.

## Setup
- L179: "We use DeepSeek-R1-Distill-Qwen-1.5B, a 1.5B-parameter reasoning model distilled from DeepSeek-R1 on roughly 800K high-quality traces" — base model is a distilled reasoning model.
- L177-178: "We train on the MATH-lighteval split of competition mathematics problems with verifiable final answers and validate on the held-out MATH-500 set at temperature 0.6" — uses MATH problem set with binary reward signal.
- L183: "We run GRPO with group size $G=8$ for 90 steps from a cold start, with a 16,384 -token context cap, on 4 NVIDIA H100 GPUs" — training configuration with group size and token budget.
- L102: "Default caps are 1,024 tokens for NoThink and 3,000 for Short; Long is uncapped" — token caps per mode to enforce behavioral distinctions.

## Headline results
- L9-10: "On a 1.5B distilled model trained on MATH, the three modes emerge without collapsing to a single choice, and the brief modes end up more accurate than Long, which shows that the router sorts problems by difficulty rather than at random. Averaged over three seeds, the resulting policy stays close to the base model's accuracy on the held-out MATH500 (0.782 vs. 0.796) while cutting the mean response length from 4,796 to 2,811 tokens (a 41% reduction)" — key result showing token reduction without major accuracy loss.
- L217-218: "On MATH-500 the router reaches this accuracy at 2,811 tokens on average, 41% fewer than the base" — in-distribution token savings on MATH.
- L233: "Free routing thus saves the most where problems are heterogeneous enough for adaptive allocation to matter, with 44% fewer tokens on GSM8K and 76% token reduction on GSM8K and at higher accuracy than the baselines at similar response length" — out-of-distribution transfer showing token savings proportional to problem heterogeneity.
- L218-220: "Figure 6 places all methods on the accuracy versus length plane. The single-mode baselines trace a Pareto frontier of fixed reasoning budgets, and free routing lies strictly above it" — routing achieves Pareto improvements over single-mode baselines.

## Limitations
- L245-246: "The results cover three seeds of one 1.5B model on one mathematical training distribution. The mode caps are task-specific and must be matched to the target task's length distribution, and uncapped validation makes brief-mode accuracy marginally optimistic relative to the trained objective" — limited to one model and one task distribution, mode caps are task-specific.
- L258-259: "Countdown's uniform difficulty gives the router no accuracy gap to learn from, so the crossover never took effect" — negative result showing routing fails when problem difficulty is uniform (Countdown task).
- L319: "Validation is uncapped, measuring production behavior — which makes brief-mode validation accuracy marginally optimistic relative to the capped objective" — validation setup doesn't exactly match training conditions.
- L246: "The most important next step is therefore breadth: establishing the mechanism on a wider range of mathematical benchmarks and then beyond mathematics" — need evaluation on broader benchmarks.

## Assumptions and conditions
- L26-27: "A mode with even a small reward edge is sampled more, reinforced more, and quickly drives the alternatives out of the policy" — assumes routing collapse is a natural failure mode without safeguards.
- L88-99: "NoThink: the model answers as quickly as possible, using little reasoning. Short: the model reasons briefly within a hard token cap. Long: the model reasons at length without a cap" — defines three modes by design constraints.
- L114-115: "With $b_{\text{NT}}/b_{\text{S}}/b_{\text{L}}=1.3/1.2/1.0$ and caps $C_{\text{NT}}/C_{\text{S}}=1024/3000$ this gives $\gamma_{\text{NT}}\!\approx\!0.99984$ , $\gamma_{\text{S}}\!\approx\!0.99994$" — specific reward parameters set to position mode crossovers at or below caps.
- L142-144: "For the first warmup_steps training steps we therefore force two rollout per group into each of NoThink, Short, and Long, generating the remaining rollouts freely" — forced warmup phase to establish routing token emission.
