## Cells

- `method name`: confirmed — JIT-Agent (JIT-Agent-27B), trained with a three-stage recipe whose last stage is Evo-GDPO — "Through this pipeline, we train JIT-Agent-27B, a harness intelligence model that can customize, repair, and evolve task-specific harnesses" (JIT-Agent., line 33)
- `method summary`: corrected — A 27B generator (trained from Qwen3.6-27B) emits executable harnesses under a fixed four-module protocol (memory, planning, action, capability orchestration). The protocol is seeded by HarnessFactory, 13 hand-written re-implemented scaffolds. Training has three stages. Stage I is SFT plus preference filtering on teacher-generated, protocol-validated harnesses. Stage II is imitation of teacher repair trajectories that make failed harnesses executable within two rounds. Stage III is Evo-GDPO, online RL that rewards proposals beating the archive's best on reward, with latency and cost normalized separately. At inference the generated harness wraps a frozen off-the-shelf backbone. A static mode generates N harnesses and executes one; a streaming mode updates the harness bank across the evaluation stream. The harness contribution is isolated with the backbone held fixed: Table 3 compares against five fixed harnesses, and Figure 4 against ReAct on six backbones. — "Second, holding the backbone fixed, we compare JIT-Agent with five reusable agent harnesses" (Baselines., line 199); "JIT-Agent is trained based on Qwen3.6-27B." (Backbone Models., line 195)

## Limitations and conditions

- "In the two remaining settings, it trails the best score by only $3.1$ and $3.9$ points while using substantially fewer tokens" (5.3, line 263) — the generated harness is not uniformly better than fixed harnesses (Claude Code on AgentIF; NanoBot on DeepSearchQA with Qwen3.6-Flash).
- "DeepPlanning-Travel is the sole exception, where the JIT-equipped GLM-5.2 remains within $1.9$ points of GPT-5.6." (5.2, line 229) — the frontier-model comparison has exceptions.
- "DeepSearchQA uses a 100-example subset; the other three benchmarks use 50-example subsets." (Figure 4 caption, 5.5) — the cross-backbone generalization rests on small subsets; no confidence intervals or seed counts are reported.
- "Training tasks come from existing agentic benchmarks and environments (Wu et al., 2025; Shi et al., 2025; Bai et al., 2026; Song et al., 2026), augmented with synthesized tasks." (Stage I: Data Preparation., line 123) — no train/evaluation overlap check is reported.
- "The frontier is therefore task-dependent, but the consistent leftward shift of the JIT points" (5.4, line 269) — cost–performance dominance is task-dependent.
- "Streaming JIT, which retrieves and updates harnesses throughout the evaluation stream" (B.1, line 327) — one mode adapts on the evaluation stream itself. The main tables do not state which mode produced them.
- "JIT-Agent generates $N$ harnesses in parallel, selects one of them, and executes only the selected harness" (Static inference., line 173) — test-time selection over N candidates is part of the method. The reported per-case cost does not say whether it includes the 27B generator's own calls.

## Other findings

- The paper has no limitations section. It also has no ablation of the three training stages, nor of the generator against an untrained or teacher-only generator, in the main text.
- The draft's open question, whether the harness contribution is isolated with the model fixed, resolves to yes: Table 3 compares five fixed harnesses and Figure 4 compares ReAct, each with the same backbone. But the frontier-model rows in Table 2 compare different models in their own default scaffolds.
