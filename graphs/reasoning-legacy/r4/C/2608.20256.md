## Limitations and conditions

- "The results cover three seeds of one 1.5B model on one mathematical training distribution." (L245) — scope of every
  result
- "The mode caps are task-specific and must be matched to the target task’s length distribution" (L245) — the method
  needs per-task tuning
- "uncapped validation makes brief-mode accuracy marginally optimistic relative to the trained objective" (L245; also
  L319) — the reported brief-mode accuracies
- "Accuracy does not rise above the base model: it dips while routing is being established" (L217) — routing is a
  token-efficiency, not an accuracy, mechanism (also L241, L377)
- "it collapsed to a single mode because Countdown’s uniform difficulty gives the router no accuracy gap to learn from"
  (L82; App. A, L257–259) — routing is learnable only where problems vary in difficulty
- "phase 2 ( $60\!\to\!90$ ) flattens the reward (all bases $1.0$ , all $\gamma=1.0$ ), so mode separation is then
  maintained by the hard caps" (L329) — the final policy is trained under a flat reward, with the balance term annealed
  to 0
- "realised length is a proxy for the routing split, which the released logs do not record per OOD benchmark" (L405) —
  the out-of-distribution routing claims ("sends nearly all of GSM8K to NoThink") are inferred from length, not measured
- On GSM8K the router's accuracy is below base: "| Base (no routing) | $0.796{\scriptstyle\pm.002}$ |
  $0.831{\scriptstyle\pm.006}$" (L385) vs 0.781 for the router (L393) — conditions the "76% token reduction" claim
